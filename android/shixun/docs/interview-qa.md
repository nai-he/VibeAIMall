# 面试问答准备

## Q1：这个项目的 AI 在哪里？

AI 能力集中在 `ai` 包：`AiIntentParser` 负责解析自然语言里的预算、场景和品类，`RecommendationEngine` 根据商品标签、预算和场景进行排序，`RecommendationResult` 输出主推、备选和推荐理由。`AiRemoteAdvisor` 负责调用真实大模型 API 生成导购回复。`AiShoppingChatEngine` 负责解析对话购买指令，例如“就买这个”“买备选1”“去购物车”。

## Q2：真实大模型 API 是怎么接的？

我把 Key 从源码里拿出来，通过 `local.properties` 或环境变量注入到 `BuildConfig`，避免泄露。客户端使用 OkHttp 调用兼容 `/chat/completions` 的接口。商品选择仍由端侧推荐引擎负责，保证可控；大模型负责生成更自然的导购解释。如果 API 失败，页面会自动保留端侧推荐，不影响加购和下单演示。

## Q3：你怎么体现产品思维？

我不是只做一个聊天框，而是从用户真实购物问题出发，拆成“需求识别 → 商品匹配 → 推荐解释 → 加入购物车 → 下单 → 订单状态”的闭环。发现页也改成了 AI 产品实验室，放高频场景入口，降低用户输入成本。

## Q4：这个项目有哪些工程化改造？

- AI 逻辑从 Activity 拆成独立模块。
- 真实 API 调用拆成 `AiRemoteAdvisor`，Key 不硬编码在源码里。
- 对话购买逻辑拆成 `AiShoppingChatEngine`，避免写死在页面里。
- 商品数据用 `ProductRepository` 统一管理，避免首页、分类、详情和 AI 推荐各维护一份数据。
- 加购逻辑抽成 `CartService`，普通商品和 AI 推荐商品复用同一套数据库写入。
- 订单查询、演示订单和状态更新抽成 `OrderService`。
- SQLite 增加推荐日志表。
- 订单状态支持筛选和流转。
- 待评价订单进入评价页，评价后写入评论表并流转为已完成。
- 个人中心入口从静态图标改为可点击功能。
- 小游戏入口修复了 NoActionBar 空指针和退出进程问题。
- 增加了针对需求解析的 JUnit 测试。

## Q5：如果继续迭代，你会做什么？

我会继续把大模型用于多轮偏好记忆、客服问答和推荐解释优化，增加推荐日志统计页，做推荐转化分析，再补 UI 自动化测试覆盖核心链路。
